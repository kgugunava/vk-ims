# Тестовое задание VK Tech: платформа для ИИ-агентов в VK WorkSpace

Три связанные части в одном репозитории:

| Каталог | Что это | Язык | Подробности |
|---|---|---|---|
| [`msgfmt/`](msgfmt/README.md) | Библиотека и CLI: разметка сообщения → чистый текст и стилевые диапазоны с позициями в UTF-16, команда `escape` | C++17, только стандартная библиотека | [README](msgfmt/README.md) |
| [`service/`](service/README.md) | Служба `ghreport`: сводка открытых issue репозиториев GitHub с пагинацией, ETag-кэшем, лимитами и повторами; Docker-образ | Go 1.22, только стандартная библиотека | [README](service/README.md) |
| [`api_tests/`](api_tests/README.md) | Интеграционные тесты `ghreport` как чёрного ящика, тестовый сервер, прокси для внедрения сбоев, самопроверка на мутантах | Python 3.10+, pytest | [README](api_tests/README.md) |

## Быстрый старт

```bash
# msgfmt
cmake -S msgfmt -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build
printf 'Привет, **мир**!' | build/msgfmt

# ghreport
(cd service && go test ./... && go build -o ghreport ./cmd/ghreport)
GITHUB_TOKEN=... service/ghreport --repos cli/cli --limit 20 --out -
docker build -t ghreport service/
docker run --rm -e GITHUB_TOKEN=... ghreport --repos cli/cli --limit 20 --out -

# api_tests против тестового сервера
python3 -m venv .venv && .venv/bin/pip install -r api_tests/requirements.txt
(cd api_tests && python3 -m stub.server --port 8080 &)
GHREPORT_BIN=$PWD/service/ghreport GITHUB_API_BASE_URL=http://127.0.0.1:8080 .venv/bin/pytest api_tests -q
```

## Проверки

Задание проверяется в Linux, поэтому полные проверки идут в контейнерах (нужен Docker):

| Команда | Что делает |
|---|---|
| `scripts/in-docker.sh ./scripts/check-msgfmt.sh` | msgfmt: clang-format; GCC 13 и Clang 18 в Release с `-Werror`; оба с ASan + UBSan; команды сборки из задания как есть |
| `scripts/check-ghreport.sh` | ghreport на Go 1.22 (минимальная версия из задания): `gofmt -l`, `go vet`, `go test -race` |
| `python3 api_tests/tools/mutation_check.py` | весь набор api_tests против 9 вариантов сервера и 13 сломанных версий ghreport |

Итоговое состояние: msgfmt — 20 тестов CTest (164 случая разбора, 1,2 млн входов в тестах свойств), сборка без предупреждений и сообщений санитайзеров; ghreport — модульные тесты всех пакетов, проверены против тестового сервера, настоящего GitHub и в контейнере; api_tests — 55 тестов, около 30 секунд, ловят все внесённые поломки сервера и службы.

## Главные решения

Подробные таблицы решений — в README частей. Самое важное:

- **msgfmt.** Правила задания важнее контрольных примеров: пример 9 им противоречит (`**жирный _и курсив_**` по правилам даёт курсив на «и курсив», а не на «и») — реализовано по правилам, оба варианта в тестах. Разбор однопроходный, поиск закрывающего маркера ограничен регионом, поэтому диапазоны никогда не пересекаются частично; поиск построен на предвычисленном индексе, так что разбор линейный (наивный вариант квадратичен на `**a **a …`). «Буква или цифра» и «пробел» — по таблицам Unicode 16.0, без зависимости от локали.
- **ghreport.** Следующая страница — только из `Link: rel="next"`; PR распознаётся по наличию ключа `pull_request`; `--since` применяется к `created_at` на стороне службы. В кэше рядом с ETag хранится `Link`, иначе пагинация из кэша обрывалась бы, если сервер не повторяет `Link` в ответе 304. Редиректы обрабатываются самой службой, чтобы каждый переход был в журнале; токен уходит только на хост API. Время и паузы внедряются, поэтому тесты повторов и лимитов не ждут.
- **api_tests.** Почти все нарушения, которые набор обязан ловить, — нарушения сервера, поэтому набор проверяет сервер напрямую, сравнивает отчёт с эталоном, вычисленным по данным сервера, а сбои (401, 429, 5xx, битый JSON) внедряет через локальный прокси. Качество набора доказано прогоном против сломанных серверов и сломанных версий службы.

## Окружение

Linux; GCC или Clang с C++17, CMake ≥ 3.20; Go ≥ 1.22; Python ≥ 3.10 и pytest ≥ 7; Docker ≥ 24; git. Разработка велась на macOS, все проверки — в Linux-контейнерах (Ubuntu 24.04, `golang:1.22`).
